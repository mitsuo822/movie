# キャラクターのアニメーション（口パク・まばたき・表情差分）

> 対象: 掛け合いのキャラクター（立ち絵）に、音声に合わせた口パク・まばたき（目パチ）・表情の差分を自動で付ける方法と、そのための立ち絵素材の差分の作り方。VOICEVOX の音素タイミングの取り出し方、音量や音声認識で口形を決める方法、Remotion で組むときの注意を扱う。
> 使う場面: 立ち絵素材を選ぶ・差分を用意するとき、Remotion のキャラクター表示部品を作るとき、口パクのずれや目パチの不自然さを直すとき。
> 調査日: 2026-11-20 ／ mc_version: 対象外 ／ VOICEVOX ENGINE は GitHub の master ブランチ、VOICEVOX エディタは main ブランチのソース（どちらも 2026-11-20 取得）。Remotion は 2026-11-20 時点の公式ドキュメント（4.0 系。5.0 で既定値が変わる項目は明記）。
> 関連: [キャラクター立ち絵の規約.md](../audio/キャラクター立ち絵の規約.md)（素材を改変・差分化してよいかの規約）, [音声合成の生成と読みの調整.md](../audio/音声合成の生成と読みの調整.md)（audio_query→synthesis の API そのもの）, [VOICEVOX利用規約.md](../audio/VOICEVOX利用規約.md), [Remotion.md](Remotion.md)（ライセンス・書き出し・タイムライン）, [テロップ・字幕.md](テロップ・字幕.md), [掛け合い形式.md](../script/掛け合い形式.md)

## 要点
- 口パクの自動化には大きく、(1) 音声合成の音素タイミングを使う、(2) 音量を使う、(3) 音声認識で音素を推定する（Rhubarb Lip Sync）、(4) 編集ソフトの内蔵機能（YMM4、AviUtl の PSDToolKit）を使う、の方法がある。【一次】[S1][S7][S8][S16]
- VOICEVOX の audio_query はモーラごとに子音・母音の音素と長さ（秒）を持つ。アクセント句の末尾には無音モーラ（pause_mora）が付くことがある。【一次】[S1]
- モーラの末尾の音素は a・i・u・e・o・N（撥音）と、無声の A・I・U・E・O・cl（促音）・pau（無音）。母音ごとに口の形を割り当てれば、5母音＋ん＋閉じ口の口パクが組める。【一次】[S3]
- 実際の音声の長さは、前後の無音（prePhonemeLength / postPhonemeLength）を足し、無音の長さを調整したあと、子音・母音・無音のすべてを話速（speedScale）で割って決まる。【一次】[S2]
- VOICEVOX エディタには設定の「保存」項目に『lab ファイルを書き出し』があり、音声と同じ名前の .lab に音素とその開始・終了時刻を保存する。時刻の単位は1秒＝10,000,000（100ナノ秒）。【一次】[S4][S5][S6]
- エディタの lab は無声母音（A・I・U・E・O）を小文字にして書くので、lab だけでは有声と無声の母音を区別できない。【一次】[S5]
- Rhubarb Lip Sync は音声ファイルから口形（基本6種＋任意3種）とその時刻を TSV / XML / JSON で出す。英語以外は phonetic 認識器を使い、英語用より精度が下がると README に書かれている。【一次】[S7]
- セル画のアニメでは、口のない顔の上に「開く」「閉じる」「半開き」などの口だけを差し替える。目の瞬きは目パチと呼ばれ、デジタルではレイヤーを重ねて同じことをする。【二次】[S12]
- 瞬き1回の長さは平均100〜150ミリ秒（UCL の研究者）または100〜400ミリ秒（Harvard の BioNumbers）、間隔はおおむね2〜10秒、実験室では平均約17回/分、読書など一点を見続けると4〜5回/分に下がる。【二次】[S11]
- Remotion では Math.random() で目パチの間隔を決めると、並列レンダリングでフレームごとに値が変わって壊れる。シードを渡す random() を使う。【一次】[S9]
- Remotion で口の画像をフレームごとに差し替えるときは <Img> を使うと、画像の読み込みが終わるまでフレームの描画を待つので、ちらつきを避けられる。【一次】[S10]
- Remotion の visualizeAudio() で音量（周波数帯ごとの振幅、0〜1）を取り、口の開きに使える。ただし frame は音声トラック上の位置を指すので、音声をずらして置いたらその分を引いて渡す。【一次】[S8]

## 詳細

### 1. 口パクの方式の比較

| 方式 | 口形を決める手がかり | 出典にある特徴 | 確度・出典 |
|---|---|---|---|
| 音素タイミング | VOICEVOX の audio_query のモーラ長、またはエディタが書き出す .lab | 母音ごとに口形を変えられる。タイミングは合成に使う値そのもの | 【一次】[S1][S2][S5] |
| 音量 | 音声の振幅（Remotion の visualizeAudio() など） | 周波数帯ごとの 0〜1 の値が得られる。母音の区別はしない | 【一次】[S8] |
| 音声認識 | 音声から音素を推定（Rhubarb Lip Sync） | 任意の録音に使える。英語以外は精度が下がる | 【一次】[S7] |
| 編集ソフト内蔵 | YMM4 の立ち絵機能、AviUtl の PSDToolKit など | 素材の形式ごとに設定方法が違う | 【未確認】[S18][S21]、【一次】[S16] |

Unreal Engine 向けの VOICEVOX 連携プラグイン（VoicevoxEngine For UE Ver1.2）は、AudioQuery からリップシンクのデータを作り、母音あ〜おのモーフを動かすモードと、1つのモーフだけを動かす簡易モードを持つ。簡易モードについて作者は次のように書いている。【二次】[S15]
> 「リップシンク再生の処理が軽くなりますが、人間が喋る時のリップシンクではなくなります。」[S15]

同じプラグインは、リップシンクを切って音だけを鳴らす設定を、心の声に使うよう勧めている。【二次】[S15]
> 「心の声の表現に使用してください。」[S15]

### 2. VOICEVOX から口パクのタイミングを取り出す

#### 2.1 audio_query の構造
audio_query の中身はアクセント句（AccentPhrase）の並びで、各アクセント句がモーラ（Mora）の並びを持つ。モーラは文字（text）、子音の音素（consonant）と長さ（consonant_length）、母音の音素（vowel）と長さ（vowel_length）、音高（pitch）を持つ。子音はないこともある（null）。【一次】[S1]
> 「モーラ（子音＋母音）ごとの情報。」[S1]

アクセント句には末尾の無音モーラ（pause_mora）が付くことがある。【一次】[S1]
> 「アクセント句の末尾につく無音モーラ。null の場合は無音モーラを付けない。」[S1]

API の呼び方（audio_query→synthesis）は [音声合成の生成と読みの調整.md](../audio/音声合成の生成と読みの調整.md) に任せる。

#### 2.2 音素の種類
ENGINE の音素一覧には pau・A・E・I・N・O・U・a・e・i・o・u・cl と子音が並ぶ。モーラ末尾の音素は a・i・u・e・o・N と、無声の A・I・U・E・O・cl・pau。【一次】[S3]
> 「この音素は無声のモーラ末尾音素（無声母音・促音・無音）である」[S3]

ENGINE は sil（無音）を含む音素を pau に変換して扱う。【一次】[S3]
> 「無音をポーズに変換」[S3]

ENGINE は、母音が無声のモーラの音高を 0 にする。【一次】[S2]

#### 2.3 実際の長さの計算（ENGINE の処理順）
ENGINE は音声合成の前に、モーラの並びに次の順で手を加える。【一次】[S2]
1. 前後に無音モーラ（長さ prePhonemeLength / postPhonemeLength、母音は sil）を足す。
2. pauseLength が指定されていれば、pau の長さをその値にする。
3. pau の長さに pauseLengthScale を掛ける。
4. すべてのモーラの母音・子音の長さを speedScale で割る（前後の無音も含む）。

> 「mora.vowel_length /= query.speedScale」[S2]

ENGINE は秒の長さを 93.75 フレーム/秒（24000/256）のフレーム数に音素ごとに丸めて合成する。丸めは偶数丸め。【一次】[S2]
> 「FRAMERATE = 93.75」[S2]
> 「`round` は偶数丸め。移植時に取扱い注意。」[S2]

1フレームは約10.7ミリ秒（1/93.75 秒の計算値）。【一次】[S2]

#### 2.4 VOICEVOX エディタの lab 書き出し
エディタの説明書は、設定の「保存」項目にある『lab ファイルを書き出し』を次のように説明している。【一次】[S4]
> 「リップシンクなどに便利な、音声の音素情報とそのタイミング情報が書かれたラベルファイルを一緒に保存します。」[S4]

音声書き出しでは全テキスト欄の音声が WAV で書き出され、既定のファイル名は `[何行目]_[キャラ名]_[テキスト冒頭].wav`。【一次】[S4]
> 「全テキスト欄の音声が WAV ファイルとして書き出されます。」[S4]

lab は WAV のファイル名の拡張子 .wav を .lab に変えた名前で保存される。【一次】[S6]

lab を作る関数（generateLabFromAudioQuery）の中身は次のとおり（2026-11-20 取得の main ブランチ）。【一次】[S5]
- 1行に、開始時刻・終了時刻・音素の3つを空白で区切って書く。時刻は秒に 10,000,000 を掛け、speedScale で割った値の累積。
- 最初と最後に、prePhonemeLength / postPhonemeLength の長さの pau を書く。
- 各モーラについて、子音があれば子音の行、続けて母音の行を書く。母音は N 以外を小文字にする。
- アクセント句の pause_mora は、長さに pauseLengthScale を掛けて書く。

> 「(mora.consonantLength * 10000000) / speedScale」[S5]

この関数は pauseLength（無音の固定長）を参照していない。ENGINE のフレームへの丸め（2.3）も再現していない。【一次】[S2][S5]

エディタは、書き出しの設定がオフでも lab を毎回生成している。【一次】[S6]
> 「大して処理能力を要しないので、書き出し設定のon/offにかかわらず生成してしまう」[S6]

全テキスト欄を1つの WAV につなげて書き出す処理では、前の欄の lab の最後の終了時刻を次の欄の開始のずらし（labOffset）にし、各欄の lab をつなげて1つの .lab にする。【一次】[S6]
> 「最終音素の終了時刻を取得する」[S6]
> 「`generateLabFromAudioQuery`で生成される文字列はすべて改行で終わるので、追加で改行を挟む必要はない」[S6]

### 3. 口の形を何種類描くか

#### 3.1 セル画の口パクと目パチ
口パクは、リミテッド・アニメーションで、台詞のときに口だけを動かす技法。セル画では「開く」「閉じる」「半開き」などの口だけのセルを、口のない顔のセルに重ね、台詞に合わせて差し替えて撮影する。【二次】[S12]
> 「口が描かれていないキャラクターの顔のセル画の上に乗せ」[S12]

表情を1枚ずつ描くより作画枚数を減らせる。日本ではテレビアニメ『鉄腕アトム』以後に広まったとされる。【二次】[S12]
> 「日本ではテレビアニメ『鉄腕アトム』の制作以後に広まった技法とされる」[S12]
> 「同様に目の瞬きを表現するのは目パチと呼ばれる。」[S12]
> 「現在のデジタル制作環境ではセル画の代わりにレイヤーを重ねるが、目的は同じである。」[S12]

#### 3.2 Rhubarb の口形（英語の音を基準にした分類）
Rhubarb Lip Sync は6〜9種類の口形を使う。A〜F の6種が基本で、キャラクターに最低限描く必要がある（訳）。原文:「the absolute minimum you have to draw for your character」[S7]。この6種は Hanna-Barbera のスタジオで考案されたと README は書く。【一次】[S7]
> 「These six mouth shapes were invented at the Hanna-Barbera studios for shows such as Scooby-Doo and The Flintstones.」[S7]

| 口形 | README の説明（要約） | 確度・出典 |
|---|---|---|
| A | P・B・M の閉じた口。X とほぼ同じだが唇に少し圧がある | 【一次】[S7] |
| B | 少し開いて歯を食いしばった口。K・S・T など多くの子音と、bee の EE | 【一次】[S7] |
| C | 開いた口。men の EH、bat の AE。A/B から D への中割りにも使う | 【一次】[S7] |
| D | 大きく開いた口。father の AA | 【一次】[S7] |
| E | 少し丸めた口。off の AO、bird の ER。C/D から F への中割りにも使う | 【一次】[S7] |
| F | すぼめた唇。you の UW、show の OW、way の W | 【一次】[S7] |
| G（任意） | 上の歯が下唇に触れる。for の F、very の V | 【一次】[S7] |
| H（任意） | 長い L の音。舌を上の歯の裏に上げる | 【一次】[S7] |
| X（任意） | 休みの口。話の切れ目に使い、話していないときの口と同じ絵にする | 【一次】[S7] |

README は、A→C→D と B→C→D が滑らかにつながるように描くよう求めている。【一次】[S7]

#### 3.3 最小構成の例（Remotion + VOICEVOX のテンプレート）
『Remotion + VOICEVOX 動画テンプレート』（nyanko3141592、MIT License）は、1920x1080・30fps で、キャラクターごとに mouth_open.png（口開き）と mouth_close.png（口閉じ）の2枚を必須にしている。表情差分は happy_open.png / happy_close.png のように表情名＋開閉で置く。【一次】[S13][S14]
> 「ずんだもん＆めたんの掛け合い紹介動画を簡単に作成できるテンプレートです。」[S13]
> 「存在しない表情は自動的に`mouth_open/mouth_close`にフォールバックします。」[S14]

同じテンプレートの説明書は、表情を多用しないこと、リアクションを最低0.5秒（15フレーム）続けることを勧めている（作者の方針）。【二次】[S14]
> 「表情差分は**多用しない**、ここぞというところで使用」[S14]
> 「リアクションは最低0.5秒（15フレーム）継続させる」[S14]

### 4. Rhubarb Lip Sync（音声から口形を自動で出す）
- 入力は WAVE（.wav）と Ogg Vorbis（.ogg）。【一次】[S7]
  > 「Supported file formats are WAVE (.wav) and Ogg Vorbis (.ogg).」[S7]
- 認識器は2つ。既定の PocketSphinx は英語だけを認識する。phonetic は言語に依存しないが、結果は PocketSphinx より不正確なことが多い（訳）。原文:「The results are usually less precise than those from the PocketSphinx recognizer.」[S7]【一次】[S7]
  > 「Use it if your recordings are not in English.」[S7]
- 台詞のテキストを --dialogFile で渡すと認識が安定する。README は常に渡すのがよいとしている。【一次】[S7]
  > 「It is always a good idea to specify the dialog text.」[S7]
- 出力は TSV（既定）・XML・JSON と、Moho / OpenToonz 用の .dat。TSV は1行に、秒の時刻・タブ・口形の名前を並べる。最終行は録音の終わりの時刻（0.01秒単位に切り捨て）で、口は必ず閉じる。【一次】[S7]
  > 「Its timestamp is always the very end of the recording (truncated to a multiple of 0.01s)」[S7]
- After Effects、Moho、OpenToonz、Spine、Vegas Pro との連携がある。--extendedShapes で使う任意の口形（G・H・X）を選べる。【一次】[S7]

日本語の音声で phonetic 認識器がどの程度合うかを示す資料は、今回の調査では見つからなかった。

### 5. まばたき（目パチ）

#### 5.1 人の瞬きの数値（Wikipedia の記述）
| 項目 | 値 | 確度・出典 |
|---|---|---|
| 1回の長さ | 平均100〜150ミリ秒（UCL の研究者）。100〜400ミリ秒（Harvard の BioNumbers） | 【二次】[S11] |
| 間隔 | おおむね2〜10秒。実験室では平均約17回/分（個人差あり） | 【二次】[S11] |
| 一点を見続けるとき | 読書などで約4〜5回/分に減る | 【二次】[S11] |
| 長い閉眼 | 1000ミリ秒を超える閉眼はマイクロスリープとされた | 【二次】[S11] |

> 「on average 100–150 milliseconds according to UCL researcher」[S11]
> 「averaging around 17 blinks per minute in a laboratory setting」[S11]

30fps に直すと、100〜150ミリ秒は3〜4.5フレーム、2〜10秒は60〜300フレーム（計算値）。【二次】[S11]

#### 5.2 Remotion で間隔をばらつかせる
Remotion は複数のページを立ち上げて並列にフレームを描くので、Math.random() の値はインスタンスごとに変わる。プレビューでは動いてもレンダリングで壊れる。【一次】[S9]
> 「While this will work during preview, it will break while rendering.」[S9]

remotion の random() にシード（数値か文字列）を渡すと、同じシードなら同じ値が返る。calculateMetadata() の中は1回しか呼ばれないので本当の乱数を使ってよい。【一次】[S9]
> 「Pass in a seed (number or string) and as long as the seed is the same, the return value will be the same.」[S9]
> 「It is safe to use true random values inside calculateMetadata(), as it is only called once and not in parallel.」[S9]

### 6. Remotion で組むときの注意

#### 6.1 画像の差し替えとちらつき
<Img> を使うと、Remotion は画像の読み込みが終わってからフレームを描く。【一次】[S10]
> 「That way you can avoid flickers if the image does not load immediately during rendering.」[S10]

- premountFor（v4.0.497 から）で、表示の何フレームか前から画像を非表示のまま読み込ませておける。【一次】[S10]
  > 「Use this prop to let the image load and decode before it becomes visible.」[S10]
- pauseWhenLoading（Player で読み込み中に一時停止）の既定は 4.0 で false、5.0 で true。【一次】[S10]
  > 「The default is false in Remotion 4.0 and true in Remotion 5.0.」[S10]

#### 6.2 音量で口を動かす（visualizeAudio）
@remotion/media-utils の visualizeAudio() は、useAudioData() や getAudioData() で読んだ音声から、そのフレームの周波数帯ごとの振幅を返す。【一次】[S8]
- 戻り値は numberOfSamples 個の配列で、各値は 0〜1。左ほど低い周波数。numberOfSamples は2のべき乗。【一次】[S8]
  > 「Must be a power of two, such as 32, 64, 128, etc.」[S8]
- 左側（低音）の値が右側よりかなり大きくなることがあり、対数で平らにする後処理の例が載っている。【一次】[S8]
  > 「Usually the values on left side of the array can become much larger than the values on the right.」[S8]
- frame は音声トラック上の位置。タイムライン上で音声をずらしたり切ったりしたら、useCurrentFrame() の値を直して渡す。【一次】[S8]
  > 「The frame always refers to the position in the audio track」[S8]
- smoothing の既定は true で、前後のフレームとの平均になる。【一次】[S8]
  > 「When set to true the returned values will be an average of the current, previous and next frames.」[S8]
- optimizeFor（v4.0.83 から）の既定は "accuracy" で、5.0 から "speed" に変わる。useWindowedAudioData() を使うときは dataOffsetInSeconds（v4.0.268 から）を渡す。【一次】[S8]
  > 「From v5.0, the default value changes from "accuracy" to "speed".」[S8]

口パクにどの帯域・しきい値を使うかの公式の指針は、visualizeAudio() のページにはない。【一次】[S8]

### 7. 表情の差分と立ち絵素材

#### 7.1 PSD 素材と PSDToolKit（AviUtl）
PSDToolKit は AviUtl の拡張編集で PSD を扱うためのツールキット。README の動作確認は AviUtl 1.10 / 拡張編集 0.92 で、使い方は配布物に同梱の『PSDToolKit説明書.html』にある（README には機能の説明がない）。【一次】[S16]
> 「PSDToolKit は AviUtl の拡張編集プラグイン上で PSD ファイルを扱えるようにするためのツールキットです。」[S16]
> 「動作確認は AviUtl version 1.10 / 拡張編集 version 0.92 で行っています。」[S16]

同じ作者の PSDTool の説明書の目次には、独自拡張として、レイヤー名に * を付けるラジオボタン化、! を付ける強制表示化、:flipx・:flipy・:flipxy の反転表示用レイヤーが並ぶ（検索要約のみ・原文未読）。【未確認】[S17]

AviUtl2 向けには PSDToolKit2 があり、導入には PSDToolKit2 本体・かんしくん・音声合成ソフト・PSD の立ち絵素材が要り、口パクと目パチの前にかんしくんの設定ファイルを作る必要があるとする解説がある（検索要約のみ・原文未読）。【未確認】[S19][S20]

#### 7.2 YMM4 の『動く立ち絵』
YMM4 の『動く立ち絵』素材は、眉・目・口・髪・顔色・体・他・後のフォルダに部位ごとの差分画像を入れる構成で、連番アニメの部位は `パーツ名.0.png` などに加えて基本の `パーツ名.png` が要り、ファイル名にドットを含むものは一覧に出ない、と公式サイトの FAQ にあるらしい（検索要約のみ・原文未読）。【未確認】[S18]

YMM4 の口パク・目パチの設定は、立ち絵素材の種類によって方法が違うとする解説がある（検索要約のみ・原文未読）。【未確認】[S21]

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。

- **タイミングは audio_query から直接計算する。** 音声は API で作るので、エディタの lab を経由せず、同じ式（モーラの子音・母音の長さ、前後の無音、pause_mora×pauseLengthScale を speedScale で割って累積）で区間を作る。pauseLength を使うなら、エディタの lab と違ってその値を反映させる。（根拠: [S1][S2][S5]）
- **口形の割り当て（初版）。** a→あの口、i→いの口、u→うの口、e→えの口、o→おの口、N→閉じ気味、cl・pau・sil→閉じ口。無声母音（A・I・U・E・O）は音高 0 なので、閉じ口か半開きを試して見え方で決める。素材が開閉2枚しかなければ、有声の母音の区間だけ開く。（根拠: [S2][S3][S12][S14]）
- **短い区間は間引く。** ENGINE の1フレームは約10.7ミリ秒、動画の1フレームは30fpsで約33ミリ秒なので、1フレーム未満の口形は前後に吸収させる。どの長さで間引くと自然かは試して決める（【実測】の対象）。（根拠: [S2]）
- **素材の差分は最小3枚から。** 閉・半開き・開の3枚（セル画の基本）で始め、余裕があれば5母音に増やす。母音ごとの絵は Rhubarb の説明（すぼめた唇＝F など）を参考に描き分ける。（根拠: [S7][S12]）
- **まばたき。** キャラクターごとにシードを変えた random() で間隔を2〜10秒（60〜300フレーム）からばらつかせ、閉じる時間は3〜4フレーム（100〜150ミリ秒）にする。聞き役も目パチは続ける。（根拠: [S9][S11]）
- **ちらつき対策。** 口・目の差分は <Img> で読み、差分を切り替える直前に premountFor で読み込ませる。（根拠: [S10]）
- **表情差分は要所だけ。** 驚き・納得などの見せ場に限り、最低15フレーム続ける（テンプレート作者の方針を出発点にし、自分たちの動画で確かめる）。（根拠: [S14]）
- **心の声の演出。** 口を動かさずに音声だけを流すと、心の声として区別できる。（根拠: [S15]）
- **人の声やAI音声以外の素材。** VOICEVOX 以外の録音（収録した声など）の口パクには、Rhubarb を phonetic 認識器＋台詞テキストで使う。精度は自分たちで確かめる。（根拠: [S7]）
- **音量方式は補助に。** visualizeAudio() の値は母音を区別しないので、口の開き具合の強弱（大声で大きく開く）だけに使う。（根拠: [S8]）

## わかっていないこと・要確認
- ENGINE が音素ごとに 93.75 フレーム/秒へ丸めることで、audio_query から計算した時刻と実際の WAV の長さがどれだけずれるか（長い台詞で累積するか）。未計測。
- VOICEVOX エディタが pauseLength（無音の固定長）を使う設定を持つか。持つ場合、lab の時刻が音声とずれるか。lab を作る関数は pauseLength を参照していない（[S5]）。
- 無声母音（A・I・U・E・O）と促音（cl）の区間に、どの口形を当てると自然に見えるか。資料は見つからなかった。
- 口形の種類（2・3・5・9種類）で視聴者の印象や維持率が変わるかの研究・データ。見つからなかった。
- Rhubarb の phonetic 認識器の日本語での精度。資料は見つからなかった。README にライセンスの記載はなく、ライセンスは未確認。
- YMM4 の『動く立ち絵』と口パク・目パチの設定、PSDTool / PSDToolKit / PSDToolKit2 のレイヤー命名規則と口パク機能の詳細。公式ページ（manjubox.net、oov.github.io）と解説サイト（vip-jikkyo.net）は今回の調査環境から読めず、検索要約しかない。

- 会話中の瞬きの頻度。Wikipedia が出典に挙げる Bentivoglio ら（1997）は読んでいない。
