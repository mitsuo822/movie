## 要点
- 説明欄の上限は資料によって書き方が違う。Studio のヘルプ（日本語版・英語版）は 5,000 文字、日本語版の「ヒント」ページは半角 5,000 文字（全角 2,500 文字）、Data API のリファレンスは 5,000 バイト。どれが実際の上限かは確かめていない（下の『わかっていないこと・要確認』を参照）。【一次】[S3][S18][S4][S5][S1]
- API ではタイトルと説明に `<` と `>` を使えない（< と > を除く有効な UTF-8 文字のみ）。【一次】[S1]
- 説明欄は［もっと見る］の前と後の2つに分かれ、最初の数行が最初に目に入る。何文字まで見えるかの公式の数値は見つからなかった。【一次】[S4]
- 長尺動画の説明欄の URL をクリックできるリンクにするには、上級者向け機能が必要。ショートの説明欄とコメントの URL はクリックできない。【一次】[S1][S9][S10]
- 説明欄のハッシュタグは、最も興味を引くとみなされたものが3つまでタイトルの所に出る。60個を超えると全部が無効になる。【一次】[S6]
- タグは、つづりを間違えられやすい語でない限り、検索での役割はごく小さい。タイトル・サムネイル・説明のほうが重要と公式が書いている。【一次】[S3][S7]
- タグの上限は API で 500 文字。タグの間のカンマと、空白を含むタグに付く引用符も数える。【一次】[S1]
- カテゴリは「視聴者が動画を見つけやすくなるように」選ぶもの。カテゴリを［教育］にした場合は、学習のタイプ（「科学実験」を含む）などを追加で選べる（日本語版は「教育目的の場合は」と訳しているが、英語版は「For Education」）。カテゴリが推薦にどう効くかの公式の説明は見つからなかった。【一次】[S3][S18]
- ゲームページのヘルプは、ゲーム動画が間違ったトピック別のチャンネルに表示される場合に、タイトル・説明・カテゴリを見直し、Studio でカテゴリが［ゲーム］で正しいゲームが選ばれているかを確かめるよう案内している。Data API の video リソースには、ゲームタイトルに当たる項目が見当たらなかった（要確認）。【一次】[S8][S1]
- クレジットを説明欄（または見に行けばわかる所）に置くよう求めるものがある: VOICEVOX（ソフトウェアの規約で、利用したことがわかるクレジット表記が必要）、東北ずん子系の音声（「VOICEVOX:ずんだもん」の形式）、YouTube オーディオライブラリのクリエイティブ・コモンズ曲（説明欄に必須）。Mojang は公式でないことの免責表示を説明などに目立つように入れるよう書いている。【一次】[S14][S15][S13][S17]
- 有料プロモーションは、動画の詳細の［有料プロモーション］のチェックボックスで YouTube に申告する必要がある（API にも項目がある）。申告すると冒頭10秒に開示メッセージが自動で出る。国内法の開示義務はクリエイターとブランドの責任とされる。【一次】[S12][S1]

| 説明 | 5,000 文字（英語版の動画の設定のヘルプは 5,000 characters、英語版の「ヒント」は 5000 characters）。日本語版の「ヒント」は半角 5,000 文字（全角 2,500 文字） | 最大 5,000 バイト。`<` `>` 以外の UTF-8 文字 | 【一次】[S3][S18][S5][S4][S1] |

  > 「プロパティ値の最大長は 5,000 バイトで、< と > を除くすべての有効な UTF-8 文字を使用できます。」[S1]
  > 「動画の説明の文字数制限は 5,000 文字です。」[S3]
  > 「説明には半角 5,000 文字（全角 2,500 文字）まで使用できます。」[S4]
  > （訳）説明は最大 5000 文字まで。「The description allows a maximum of 5000 characters.」[S5]
- 日本語のヘルプには、AI 技術で翻訳した内容を含む場合があるという注記が付いている。全角 2,500 文字という書き方は、読んだ範囲では日本語版の「ヒント」ページにだけあった。【一次】[S4][S5]
  > 「このページには、AI 技術を使用して翻訳されたコンテンツが含まれている場合があります。」[S4]
- タグの数え方の例: 【一次】[S1]
  > 「リスト内のアイテム間のカンマも上限にカウントされます。」[S1]
- タイトルの選び方は [タイトル](../planning/タイトル.md) に任せる。

### 2. 説明欄の見え方と書き方（公式のヒント）
- 説明は［もっと見る］を押す前に見える部分と、押した後に見える部分に分かれる。最初の数行に動画の説明を書くよう公式が勧めている。【一次】[S4]
  > 「説明の上部の数行は最初に視聴者の目に留まるため、この部分に動画の説明を記載するようにしてください。」[S4]
- 見える行数・文字数の公式の数値は、読んだヘルプには書かれていなかった。代わりに、検索結果・再生ページ・いろいろなモバイル端末での表示を確かめるよう書いている。【一次】[S4]
- 検索キーワードは動画と説明の文字列に照合される。主なキーワードを1〜2語決め、説明とタイトルの両方で目立つように使うよう勧めている。【一次】[S4]
  > 「検索キーワードは動画と説明内のテキストと照合されます。」[S4]
- 動画ごとに独自の説明を付けるよう勧めている。一方で、全動画に共通の情報は「デフォルトの説明」に入れて自動で入れられる。【一次】[S4]
- 説明欄は文字だけだが、太字・斜体・取り消し線を付けられる。行頭に `*` `+` `-` のどれかと空白を入れると箇条書きになる（ヘルプではモバイルの操作の段落に書かれていて、パソコンで同じように表示されるかは書かれていない）。【一次】[S3][S4]
- 協力者のクレジットの書き方として、協力してくれたチャンネルや人物をメンションするよう勧めている。【一次】[S4]
  > 「クレジットでコラボレーションを紹介し、協力してくれたチャンネルや人物をメンションしましょう。」[S4]

### 3. 説明欄のリンク
- 長尺動画のコメントや説明の URL をクリックできる外部リンクにするには、チャンネルで上級者向け機能を有効にする必要がある。【一次】[S10][S9][S1]
  > 「クリック可能な外部リンクを追加するには、チャンネルで上級者向け機能の利用を有効にする必要があります。」[S10]
- 上級者向け機能は、チャンネル履歴が十分なら自動で承認されやすく、身分証明書か動画の本人確認でもすぐ使える（中級者向けは電話番号の確認）。【一次】[S9]
- 機能の表（2026-11-20 取得）では、『長尺動画の説明と投稿へのクリック可能なリンクの追加』のほか、『チャプターの追加』『動画と投稿へのコメントの固定』も上級者向け機能の行に並んでいる。【一次】[S9] チャプターの条件は [チャプター・カード・終了画面](チャプター・カード・終了画面.md)、機能の段階は [新規チャンネルの立ち上げ](../channel/新規チャンネルの立ち上げ.md) を見る。
- ショートの説明欄とコメントの URL はクリックできない。【一次】[S10]
  > 「注: スパムや詐欺行為を減らすため、ショート動画のコメントやショート動画の説明に記載されている URL はクリックできません。」[S10]
- チャンネル プロフィールには最大14件のリンクを表示できる。【一次】[S10]
- ユーザーを外部サイトに誘導することだけが目的のコンテンツはスパムに関するポリシーの対象になる。【一次】[S11]
  > 「プラットフォーム外への誘導: ユーザーを YouTube から外部サイトに誘導することのみを目的として作成されたコンテンツ。」[S11]

### 4. ハッシュタグ
- タイトルか説明に # で始まる語を書くと、同じハッシュタグの動画の検索結果ページへのリンクになる。【一次】[S6]
- 説明欄のハッシュタグのうち3つまでがタイトルの所に出る。どれが出るかは YouTube が選ぶ。【一次】[S6]
  > 「動画の説明に追加したすべてのハッシュタグのうち、最も興味を引くとみなされたハッシュタグが 3 つまで、動画のタイトルに表示されます。」[S6]
- 60個を超えると全部が無効になる。タグが多すぎると、アップロード動画や検索結果から動画が除かれることがある。【一次】[S6]
  > 「1 つの動画またはプレイリストに 60 個を超えるハッシュタグを追加すると、そのコンテンツのすべてのハッシュタグが無効になります。」[S6]
- ハッシュタグには空白を入れられない（語をつなげて書く）。動画と直接関係のないハッシュタグは削除の原因になる。【一次】[S6]
- ハッシュタグ以外の説明的なタグや、繰り返しの文章を説明欄に並べることは禁止されている。【一次】[S6]
  > 「ハッシュタグの追加は許可されていますが、それ以外の通常の説明的なタグや何度も繰り返される文章を説明欄に入力することは、以前と同様に禁止されています。」[S6]

### 5. タグ
- タグは Studio の［詳細］で［すべて表示］を開いて入れる。【一次】[S7]
- 公式は、検索ではタイトル・サムネイル・説明のほうがタグより重要で、タグが役に立つのはつづりを間違えられやすい場合だと書いている。【一次】[S7][S3]
  > 「動画の検索時には、動画のタイトル、サムネイル、説明などのメタデータのほうがタグよりも重要な役割を果たします。」[S7]
  > 「タグは、スペルを間違えられやすいものが動画のコンテンツである場合に役に立つことがあります。その場合を除けば、動画の検索時にタグが果たす役割はごく小さなものです。」[S7]
- 説明欄にタグを過度に入れるとポリシー違反になる。【一次】[S7]
  > 「注: 動画の説明にタグを過度に追加すると、スパム、欺瞞行為、詐欺の禁止に関するポリシーに違反することになります。」[S7]
- ゲームページのヘルプでも、タグは数より質だと書いている。【一次】[S8]
- Mojang の利用ガイドラインには、関係のない製品のキーワードや検索タグに Minecraft の名前を使わないという項目がある（製品・サービスの名前の付け方の節）。【一次】[S17]
  > （訳）関係のない製品や侵害品・偽造品のキーワードや検索タグにわれわれの名前を使わない。「Don’t use our name as keywords or search tags for products that have no relationship with them or that are infringing or counterfeit」[S17]

### 6. カテゴリ
- Studio のヘルプの説明は、カテゴリは視聴者が動画を見つけやすくするために選ぶ、というもの。カテゴリが［教育］の場合は追加の項目を選べる。日本語版は「教育目的の場合は」と書いているが、英語版の原文は「For Education」で、［教育］カテゴリを選んだときの項目と読める。日本語版には AI 翻訳を含む場合があるという注記がある。【一次】[S3][S18]
  > 「視聴者が動画を見つけやすくなるように、カテゴリを選択します。教育目的の場合は、次のオプションを選択できます。」[S3]
  > （訳）視聴者が動画を見つけやすくなるようにカテゴリを選ぶ。［教育］の場合は次のオプションを選べる。「Select a category so viewers can find your video more easily. For Education, you can choose the following options:」[S18]
- ［教育］の追加項目は、タイプ・問題・教育制度・レベル・試験/コース/基準。タイプの選択肢に「科学実験」（英語版は science experiment）がある。【一次】[S3][S18]
  > 「学習のタイプとして、アクティビティ、コンセプトの概要、ハウツー、講義、問題解決のチュートリアル、現実世界での応用、科学実験、ヒントなどから選択します。」[S3]
- ゲームページのヘルプは、カテゴリを［ゲーム］にしていることと、正しいゲームが選ばれていることを並べて確かめるよう書いている（次の節）。ゲームを選ぶ欄がどの条件で出るかは、読んだ資料には書かれていなかった。【一次】[S8]
- 選べるカテゴリの一覧と ID は国ごとに API の videoCategories.list で取れる（regionCode に国コード、hl に表示言語）。呼び出しのコストは1ユニット。hl の既定値は en_US。【一次】[S2]
- videos.update で snippet を更新するときは categoryId の指定が必須。【一次】[S1]
- カテゴリ（ゲーム／科学と技術／教育）の違いが推薦や検索の順位にどう影響するかについて、読んだ公式資料には説明がなかった。推薦の公式の説明は [推薦の仕組み](推薦の仕組み.md) を見る。

### 7. ゲームタイトルの関連付け（ゲームページ）
- YouTube は、あるゲームの存在感が高まるとそのゲームのページを自動で作る。ゲーム動画の再生中は、説明の下にそのゲームページが出る。【一次】[S8]
  > 「ゲーム動画の視聴中、動画の説明の下にゲームページが表示されます。」[S8]
- ゲームページに集める動画は、動画の中心となるトピックをアルゴリズムが判別して決める。ゲームページは YouTube の編集上の見解を表すものではないと書かれている。【一次】[S8]
- ゲーム動画が間違ったトピック別のチャンネルに表示される場合は、タイトル・説明・カテゴリを見直し、Studio でカテゴリが［ゲーム］で正しいゲームが選ばれているかを確かめるよう案内している（自動生成ゲームページへの掲載についての問いの答えとして書かれている）。【一次】[S8]
  > 「ゲーム動画が間違ったトピック別のチャンネルに表示される場合は、タイトル、説明、カテゴリを確認してください。」[S8]
  > 「YouTube Studio でカテゴリを [ゲーム] に設定していることと、正しいゲームが選択されていることを確認してください。」[S8]
- Data API の video リソースのリファレンスを読んだ範囲では、ゲームタイトルを指定する項目は見当たらなかった（topicDetails はトピック ID の一覧で、ゲームのトピックの例を載せている）。API だけでゲームを関連付けられるかは要確認。【一次】[S1]

### 8. 説明欄のその他の機能
- 動画の帰属情報を書くときの形式を Studio のヘルプが示している（英語版は video attributions）。帰属情報が何を指すか（他人の動画を使ったときの出典を含むか）は、ヘルプに説明がない。【一次】[S3][S18] 引用の要件は [引用と著作権](../legal/引用と著作権.md) を見る。
  > 「動画の帰属情報を入力する場合は、[チャンネル名] [動画タイトル] [動画 ID] の形式を使用します。」[S3]
- 説明に英語の Correction（1か所）または Corrections（複数）と書き、改行して修正箇所のタイムスタンプと理由を書くと、修正のセクションになる。言語にかかわらず英語で書く。チャプターの後に表示され、視聴中に［修正を見る］の情報カードが出る。【一次】[S3]
  > 「注: 違反警告を受けたままのチャンネルや、一部の視聴者に対して不適切となり得るコンテンツの場合、修正機能は利用できません。」[S3]
  公開後の訂正の手順全体は [事実確認と訂正](../script/事実確認と訂正.md) に任せる。
- 説明にタイムスタンプ（例: 00:00）を入れるとチャプターになる。【一次】[S1] 条件は [チャプター・カード・終了画面](チャプター・カード・終了画面.md)。
- 誤解させるタイトル・サムネイル・説明で別の内容の動画をクリックさせることは、スパムに関するポリシーの「悪質なクリックベイト」に当たる。【一次】[S11]
  > 「悪質なクリックベイト: ユーザーを欺くようなタイトル、サムネイル、説明、画像を使用して、謳い文句とは異なる内容の動画をクリックさせる行為。」[S11]

### 9. クレジット・免責表示のまとめ（置き場）

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。

- **説明欄の組み立てを固定する。** 上から (1) 何を確かめた動画かの1〜2文と結論のヒント、MC のバージョン（Java Edition 1.21.x など）、(2) チャプター、(3) 出典・参考資料、(4) クレジット・免責表示の定型ブロック、(5) ハッシュタグ3個以内。最初の数行が［もっと見る］の前に出るので、(1) に主なキーワード（マインクラフト、物理、題材の語）を入れる。（根拠: [S4][S6][S1]）
- **定型ブロックは「デフォルトの説明」に入れず、台本から毎回生成する。** 声のキャラクター・BGM・mod は動画ごとに変わるので、`experiments/*/experiment.yaml` やパイプラインの設定から生成し、漏れを機械的に防ぐ。（根拠: [S4][S14][S15][S13]）
- **送る前の検査をパイプラインに入れる。** (a) タイトルと説明から `<` `>` を除く・置き換える（不等式 v < 1 などを書く物理動画では特に必要。「＜」「＞」など全角の記号が通るかは要確認）、(b) 説明のバイト数を UTF-8 で数え、5,000 バイトを超えないよう警告する、(c) タグ全体をカンマ・引用符込みで 500 文字以内にする、(d) ハッシュタグは3個前後にとどめ、60個に近づけない。（根拠: [S1][S6]）
- **タグには時間をかけない。** マイクラ・minecraft・マインクラフトのような表記ゆれと、題材の別名（例: 空気抵抗とその英語名）を数個入れる程度にする。（根拠: [S7][S3]）
- **カテゴリは2案を試す価値がある。** ［ゲーム］はゲームページのヘルプが正しいゲームの選択とあわせて確かめるよう書いているカテゴリで、［教育］なら「科学実験」のタイプを付けられる。どちらが良いかの公式の根拠はないので、シリーズの初期に両方を使い、アナリティクスのトラフィックソースを比べる。（根拠: [S3][S18][S8]）- **ゲームの選択は人の確認の関門で Studio から行う。** API にゲームタイトルの項目が見当たらないため、非公開アップロード後に人が Studio でカテゴリとゲームを確かめる手順を関門のチェックリストに入れる。（根拠: [S8][S1]）
- **説明欄のリンクは上級者向け機能が付くまでクリックできない前提で書く。** 立ち上げ直後は出典 URL がクリックできない可能性があるので、出典は資料名も併記する。ショートの説明欄の URL はクリックできないので、ショートでは関連動画の機能で長尺へつなぐ（関連動画の追加も上級者向け機能の行にある）。（根拠: [S9][S10][S1][S3]）
- **Mojang の免責表示を定型ブロックに入れるかは mcp の Mojang利用ガイドラインのファイルの結論に合わせる。** 入れる場合は原文の型（NOT AN OFFICIAL MINECRAFT …）に合わせる。（根拠: [S17]）
- **誤りが見つかったときは説明欄の Correction 機能を使う。** 違反警告があると使えないので、警告を受けないことがこの点でも重要。（根拠: [S3]）

## わかっていないこと・要確認
- 説明の上限が実際に「5,000 文字」か「5,000 バイト」か。Studio と API で違うのか、日本語の説明を API で送ったときに何文字で拒否されるかを試験投稿（非公開）で確かめる。API の上限がバイト数どおりなら、日本語の文字は UTF-8 で多くが1文字3バイトになるため【未確認】（UTF-8 の仕様は今回読んでいない）、日本語だけの説明は 1,700 文字弱で上限になる計算になる。これは計算で、確かめていない。
- 説明欄が［もっと見る］の前に何行・何文字見えるか（パソコン・スマホ・検索結果）。公式の数値はなかった。第三者の記事の数値は今回は確かめていない。
- 全角の「＜」「＞」を API のタイトル・説明に使えるか。
- Data API でゲームタイトルを設定する方法があるか（読んだ範囲の video リソースには項目がなかった）。ゲームを選べるのは［ゲーム］カテゴリのときだけか。
- 日本（regionCode=JP）で選べるカテゴリの一覧と ID。videoCategories.list で取得して記録する。
- カテゴリの違い（ゲーム／科学と技術／教育）が推薦や検索に影響するか。公式の説明は見つからなかった。
- タグのヘルプは違反になる先を「スパム、欺瞞行為、詐欺の禁止に関するポリシー」と書いているが、取得したポリシーのページの題名は『スパムに関するポリシー』だった。読んだ範囲のポリシー本文には、タグの入れすぎという項目名は見当たらなかった。ポリシーの改定・統合の経緯は未確認。
- 機能の表で『チャプターの追加』が上級者向け機能の行に並んでいる。新しいチャンネルで説明欄のタイムスタンプからチャプターが作られるかを、[チャプター・カード・終了画面](チャプター・カード・終了画面.md) の記述と照らして確かめる。
- DOVA-SYNDROME の規約ページは、今回の取得では http への転送で読めなかった（[BGMと効果音](../audio/BGMと効果音.md) を参照）。
- Mojang の免責表示が YouTube の動画の説明欄に必要か（ガイドラインの基本の節の解釈）。mcp 側の結論を待つ。
