# 音声合成の生成と読みの調整（VOICEVOX ENGINE）

> 対象: VOICEVOX ENGINE の HTTP API で台本からセリフ音声を作る技術的な手順（audio_query→synthesis、話者・スタイル ID、出力形式、GPU 版と処理時間）と、読み・アクセントの直し方（ユーザー辞書、AquesTalk 風記法、英単語・数字の読み）、長文の分割、2人分の音声を台本から並べる方法。規約・クレジットは扱わない。
> 使う場面: 音声生成スクリプトを書くとき／台本の読みを確認する関門の前／読み間違いを直すとき／生成が止まったとき
> 調査日: 2026-11-20 ／ 対象ソフト: VOICEVOX ENGINE（GitHub master ブランチ、2026-11-20 取得）、VOICEVOX エディター 0.26.3（変更履歴の最新、2026-11-20 取得） ／ mc_version: なし（MC非依存。提案節に出すMC用語の例はバージョン不問）
> 関連: [VOICEVOX利用規約.md](./VOICEVOX利用規約.md)（クレジット・キャラ規約）, [音量とラウドネス.md](./音量とラウドネス.md), [掛け合い形式.md](../script/掛け合い形式.md)（話速・間のテンポ）, [Remotion.md](../editing/Remotion.md), [テロップ・字幕.md](../editing/テロップ・字幕.md), [事実確認と訂正.md](../script/事実確認と訂正.md)

## 要点
- VOICEVOX ENGINE は HTTP サーバーで、`POST /audio_query`（テキスト→合成用クエリJSON）→ `POST /synthesis`（クエリ→WAV）の2段階で音声を作る。既定のポートは 50021。【一次】[S1][S12]
- `speaker` 引数に渡すのは `/speakers` が返す**スタイルの id**（キャラ名ではない）。id とスタイルの対応はバージョンで変わりうるので、毎回 `/speakers` から引く。【一次】[S1]【二次】[S18]
- 出力は WAV。既定のサンプリングレートは 24000Hz のモノラルで、`outputSamplingRate` と `outputStereo` で変えられる。公式は、上げても品質は上がらないと書いている。【一次】[S1][S3][S5][S11]
- 話速・音高・抑揚・音量・前後の無音・句読点の無音は、すべてクエリJSONの数値を書き換えて調整する（既定は話速1・前後の無音0.1秒など）。【一次】[S2][S3][S4]
- 読みは3段階で直せる。ユーザー辞書（API で追加・編集・削除）、クエリの `kana`（AquesTalk 風記法）を書き換えて `/accent_phrases?is_kana=true` で取り直す方法、エディターでの読み・アクセント修正。【一次】[S1][S11]
- 辞書の発音はカタカナしか受け付けない（API が検証する）。品詞を省くと固有名詞、優先度を省くと 5 になる。【一次】[S8][S9][S10]
- 辞書にない英単語は、0.24.0 以降、既定でカタカナ読みに変換される。ただし**全部大文字の語と1文字の語は変換せず、1文字ずつアルファベット読み**になる（例: VOICE→ブイオーアイシーイー）。【一次】[S1][S7][S13]
- 小数の読みが崩れる報告がある（63.3 が 60 と 3.3 のように読まれる）。文字起こしで台本と照らしても見つからないので、合成の前に `audio_query` が返す読みで確かめるやり方が紹介されている。【二次】[S14]
- セリフの長さ（秒）は、合成しなくても `audio_query` のモーラ長を足せば出せる。エンジンは各音素の長さを 93.75 フレーム/秒（24000/256）で丸めているので、合計は WAV の実測とわずかにずれる。疑問文では語尾に 0.15 秒のモーラが足される。【一次】[S4]【二次】[S15]
- CPU だけでも合成は実時間の約9倍速だったという実測がある（1台の Mac、2026年8月）。長文を一括で投げるとエンジンがエラーを出さずに停止した組み合わせがあり、300字ずつに分けると完走して速くもなった。【二次】[S17]
- Windows の GPU 版は DirectML で動く。Mac は GPU モードに対応していない。GPU モードでは長文でメモリ不足になりやすい。【一次】[S11][S12]
- エディターにも自動化に使える機能がある。`キャラ名,セリフ` の形式で書いたテキストの読み込み、リップシンク用の lab ファイル書き出し、ルビ記法 `{対象|よみ}`。【一次】[S11]

## 詳細

### 1. エンジンの構成と起動
VOICEVOX ENGINE はエディターとは別のプログラムで、HTTP リクエストを送ると音声合成を行う。【一次】[S1]
> 「実態は HTTP サーバーなので、リクエストを送信すればテキスト音声合成できます。」[S1]

- エディターかエンジンを起動していれば、`http://127.0.0.1:50021/docs` で起動中のエンジンの API ドキュメントが見られる。ポートは既定で 50021。【一次】[S1][S12]
- Docker イメージがあり、CPU 版は `voicevox/voicevox_engine:cpu-latest`、GPU 版は `voicevox/voicevox_engine:nvidia-latest`（`--gpus all` を付けて実行）。【一次】[S1]
- 起動引数: `--use_gpu`（環境変数 `VV_USE_GPU`）、`--cpu_num_threads`、`--load_all_models`（起動時に全モデルを読み込む）、`--enable_cancellable_synthesis`、`--disable_mutable_api`（辞書や設定を変える API を無効にする）など。【一次】[S1]
- CPU のスレッド数を指定しないと、論理コア数の半分を使う。【一次】[S1]
> 「CPU スレッド数が未指定の場合は、論理コア数の半分が使われます。」[S1]
- リクエストとレスポンスの文字コードはすべて UTF-8。【一次】[S1]
- CORS: 既定では localhost・127.0.0.1・app://・ブラウザ拡張・Origin なし以外からのリクエストを受け付けない。設定は `http://127.0.0.1:50021/setting` で変え、反映には再起動が要る。【一次】[S1]
- `/synthesis` は通信を切っても計算を最後まで続ける。途中で止めたいときは `/cancellable_synthesis`（実験的機能、起動引数で有効化）を使う。【一次】[S1]
- エディター 0.26.0 で、エンジンをエディターとは別にアップデートできるようになった。【一次】[S13]

### 2. 基本の流れ: audio_query → synthesis
1. `POST /audio_query?speaker=<スタイルid>&text=<URLエンコードした文>` で合成用クエリ（JSON）を得る。【一次】[S1][S3]
2. 必要ならクエリの数値や `accent_phrases` を書き換える。【一次】[S1]
3. `POST /synthesis?speaker=<スタイルid>` の本文にクエリJSONを送ると WAV が返る。【一次】[S1][S3]

> 「`speaker` に指定する値は `/speakers` エンドポイントで得られるスタイルの情報にある `id` です。互換性のために `speaker` という名前になっています。」[S1]

ほかに使えるエンドポイント:
- `/multi_synthesis`: 複数のクエリをまとめて合成し、`001.wav`、`002.wav`… を入れた zip を返す。【一次】[S3]
- `/connect_waves`: base64 にした複数の WAV を1つの WAV につなぐ。【一次】[S3]
- `/streaming_synthesis`: 合成しながら音声を少しずつ返す。`segment_length` は1回に合成する長さ（秒）。【一次】[S1]
- `/audio_query_from_preset`: `presets.yaml` に書いたプリセット（キャラ・話速など）からクエリを作る。【一次】[S1]
- `/accent_phrases`・`/mora_data`・`/mora_length`・`/mora_pitch`: アクセント句から音素の長さや音高を計算し直す（クエリ編集用）。【一次】[S3]

### 3. 合成用クエリ（AudioQuery）のパラメータ
| 項目 | 意味 | `/audio_query` が入れる既定値 | 確度・出典 |
|---|---|---|---|
| `speedScale` | 全体の話速。各モーラの子音・母音の長さをこの値で割る | 1 | 【一次】[S2][S3][S4] |
| `pitchScale` | 全体の音高 | 0 | 【一次】[S2][S3] |
| `intonationScale` | 全体の抑揚。有声モーラの平均音高からの差に掛ける | 1 | 【一次】[S2][S3][S4] |
| `volumeScale` | 全体の音量。波形に掛ける | 1 | 【一次】[S2][S3][S5] |
| `prePhonemeLength` / `postPhonemeLength` | 音声の前・後の無音（秒） | 0.1 / 0.1 | 【一次】[S2][S3] |
| `pauseLength` | 句読点などの無音の長さ（秒）。null なら使わない | null | 【一次】[S2][S3] |
| `pauseLengthScale` | 句読点などの無音の長さの倍率 | 1 | 【一次】[S2][S3][S4] |
| `outputSamplingRate` | 出力のサンプリングレート | エンジンの既定値（README では 24000Hz） | 【一次】[S1][S2][S3] |
| `outputStereo` | ステレオで出すか | false | 【一次】[S2][S3] |
| `kana` | AquesTalk 風記法の読み。**読み取り専用で、合成では無視される** | エンジンが作る | 【一次】[S2][S3] |

> 「句読点などの無音時間。nullのときは無視される。デフォルト値はnull」[S2]
> 「[読み取り専用]AquesTalk 風記法によるテキスト。音声合成用のクエリとしては無視される」[S2]

- エンジン内部では、前後の無音を付けたあとに話速を適用する。つまり `speedScale` を上げると前後の無音も短くなる。【一次】[S4]
- エディターの右欄のパラメータ（話速、音高、抑揚、音量、間の長さ、開始無音・終了無音）はこの値に当たる。抑揚は小さいほど棒読みに近い。【一次】[S11]
- 「間の長さ」の一括制御はエディター 0.22.0 で入った。【一次】[S13]
- 各アクセント句は `moras`（モーラの一覧。子音・母音の音素と長さ、音高）、`accent`（アクセント位置）、`pause_mora`（句末の無音モーラ。null なら付けない）、`is_interrogative`（疑問形か）を持つ。【一次】[S20]

### 4. 出力形式とサンプリングレート
> 「生成される音声はサンプリングレートが 24000Hz と少し特殊なため、音声プレーヤーによっては再生できない場合があります。」[S1]

- `/synthesis` は Python の soundfile で `format="WAV"` として書き出す（サブタイプは指定していない）。【一次】[S3]
- `outputSamplingRate` がエンジンの値と違えば soxr で変換し、`outputStereo` が true なら同じ波形を左右に複製する。【一次】[S5]
- エディターの設定にもサンプリングレートの変更がある。【一次】[S11]
> 「サンプリングレートを高くしても音声の品質は上がりません。」[S11]
- エディターの設定「音声をステレオ化」は、モノラルをステレオにして再生・保存する。【一次】[S11]

- 個人の記事が `/speakers` から取った一覧の一部（取得したバージョン・日付は不明）: 【二次】[S18]

### 6. 読み・アクセントの直し方
#### 6-1. ユーザー辞書（API）
- `GET /user_dict` で一覧、`POST /user_dict_word` で追加、`PUT /user_dict_word/{word_uuid}` で修正、`DELETE /user_dict_word/{word_uuid}` で削除。追加に必須の引数は `surface`（単語）、`pronunciation`（カタカナの読み）、`accent_type`（アクセント核の位置、整数）。成功すると単語の UUID が返る。【一次】[S1]
- インポートは `POST /import_user_dict`（重複を上書きするかを `override` で指定）、エクスポートは `GET /user_dict`。エンジンの設定ページ（`/setting`）からも出し入れできる。【一次】[S1][S9][S12]
- 任意の引数 `word_type` は PROPER_NOUN（固有名詞）・COMMON_NOUN（普通名詞）・VERB（動詞）・ADJECTIVE（形容詞）・SUFFIX（語尾）のどれか。省くと固有名詞になる。【一次】[S9][S10]
- 任意の引数 `priority` は 0〜10 の整数。省くと 5 になる。【一次】[S8][S9][S10]
> 「単語の優先度（0から10までの整数）。数字が大きいほど優先度が高くなる。1から9までの値を指定することを推奨」[S9]
- 発音は正規表現 `[ァ-ヴー]+` で検査され、カタカナ以外はエラーになる。捨て仮名の連続（「ッ」の後のものなどを除く）も無効。アクセント型は 0 以上、モーラ数以下でなければならない。【一次】[S8]
- 単語（surface）の半角英字は全角に置き換えて保存される。【一次】[S8]
- エディターでは「設定」→「読み方＆アクセント辞書」で登録でき、読みはひらがなでもカタカナでも入力できる。登録が効かないときは単語優先度を上げるよう案内している。【一次】[S11][S12]
- 辞書機能はエディター 0.11.0 で追加され、優先度の変更は 0.13.0 で入った。【一次】[S13]

#### 6-2. AquesTalk 風記法でアクセント句を直す
`/audio_query` の結果の `kana` には、エンジンが判断した読みが AquesTalk 風記法で入っている。これを書き換えて `/accent_phrases?speaker=<id>&is_kana=true` に送るとアクセント句が返るので、クエリの `accent_phrases` を差し替えて合成する。【一次】[S1]

記法のきまり【一次】[S1][S3]:
- カナはすべてカタカナで書く。
> 「アクセント句は `/` または `、` で区切る。 `、` で区切った場合に限り無音区間が挿入される。」[S1]
- カナの前に `_` を付けると、そのカナは無声化される。
- アクセント位置は `'` で示す。すべてのアクセント句に1つずつ必要。
- アクセント句の末尾に全角の `？` を付けると疑問文の発音になる。
- README の例: エンジンは「ディープラーニングは万能薬ではありません」を `ディ'イプ/ラ'アニングワ/バンノオヤクデワアリマセ'ン` と読んだ。これを `ディイプラ'アニングワ/バンノ'オヤクデワ/アリマセ'ン` に直して合成している。【一次】[S1]
- 記法が正しいかは `/validate_kana` で調べられる。【一次】[S3]

#### 6-3. エディターでの修正
- アクセント欄で文字の間をクリックすると、語の区切りをつないだり切ったりできる。アクセント位置は読みの上のバーを左右に動かして変える。【一次】[S11]
- 読みは、アクセント欄で読みをクリックすると後から直せる。直した箇所以外の調整はそのまま残る。【一次】[S11]
- 無声化されたモーラはバーが灰色になり、クリックで無声化を解ける。
> 「無声化できるものはイ行とウ行だけです。」[S11]
- ルビ機能: 表示するテキストを変えずに、読み方だけを変えられる。
> 「テキストに{ルビ対象|よみかた}と書くことでテキストの読み方を変えられるようになります。」[S11]
- メモ機能: テキストを `[]`（全角の `［］` も可）で囲むと、テキスト中にメモを書ける。メモ・ルビ機能はエディター 0.15.0 で入った。【一次】[S11][S13]

### 7. 英単語・アルファベットの読み
> 「辞書に登録されていない英単語は、デフォルトで自然にカタカナ読みします。」[S1]

- 無効にするには `/audio_query` に `enable_katakana_english=false` を付ける。README の例では、無効にすると「synthesis」が1文字ずつのアルファベット読み（エスワイエヌティー…）になる。【一次】[S1]
- この機能はエディター 0.24.0 の「辞書に登録されていない英単語の自然なカタカナ読み」。【一次】[S13]
- 変換の対象は、OpenJTalk が読みを知らない語（未知語）で、かつ半角英字だけの語（全角英字は半角にしてから判定）。英単語どうしの間にある全角スペース（無音として扱われるもの）は、読みが不自然になるため削除される。【一次】[S6]
- 変換には kanalizer というライブラリを使う。語は大文字の位置で分ける（キャメルケース対策。例: VoiceVox → Voice と Vox）。【一次】[S7]
- 変換しない語: 1文字の語と、全部大文字の語。これらは OpenJTalk の対応表で1文字ずつ読む（A→エー、Z→ズィー など）。【一次】[S7]
> 「全て大文字の場合はカタカナへ変換しない」[S7]
- ソースには、全部大文字の語を1文字ずつに分ける動作が利用者にとって最適かは検討中という TODO コメントがある。【一次】[S7]

### 8. 数字・単位・記号の読み
公式資料には、数字や単位・記号の読み方の規則は見つからなかった（README・使い方・Q&A を確認）。以下は個人の記事。
- 2026年9月の記事: 整数部が2桁で一の位が0でない小数が崩れた。63.3 が「ロクジュウ｜サンテン｜サン」（60 と 3.3）、18.9 が「ジュウ｜ハッテン｜キュウ」になった。3001 も 3000 と 1 に分かれ、0.12ドル は「レイテンジュウニドル」と読まれた。VOICEVOX のバージョンは書かれていない（話者は春日部つむぎ、1.4倍速）。【二次】[S14]
> 「整数の部分が2桁で、一の位が0じゃない小数。これが、十の位だけ切り離されて、一の位が小数点とくっつく。」[S14]
- 同じ記事によると、誤読した音声を文字起こしすると「8」のような正しい文字が返ってくるので、台本と照らしても誤読が見つからない。対策として、台本から小数と3桁以上の数字を正規表現で全部取り出し、合成の前にエンジンが返すカタカナ読みを目で確かめている。【二次】[S14]
- 同じ記事は、自前の読み替え辞書に読みをひらがなで書くと「は」が助詞として「ワ」と読まれた（「ハチ」が「ワチ」）、カタカナに直すと37語の誤読が消えた、と報告している。【二次】[S14]
- 同じ記事は、上書きしたい語は優先度9にするとよいとし、理由を次のように書いている。【二次】[S14]
> 「既定の8のままだと無視されることがあります。」[S14]
  - ※エンジンのソースでは、API で優先度を省いたときの値は 5【一次】[S10]。記事の言う「既定の8」がどのツールの既定値かは、記事からはわからない。
- 同じ記事は、品詞によって語の区切り方が変わる（普通名詞で登録すると後ろの名詞とつながった）とも書いている。【二次】[S14]
- 表示用と読み用で原稿を2つ持ち、読み用では「AI」を「エーアイ」と開いてからエンジンに送る、というやり方の記事もある。【二次】[S15]
- スライドから掛け合い動画を作るツール PPVoice は、`{$\frac{a+b}{2}$|にぶんのエープラスビー}` のように書くと、字幕には数式を表示し、読みは後ろの文字列にする。【二次】[S19]

### 9. 長文の分割
- 公式 Q&A: 長いテキストが再生できないのはメモリ不足が原因で、GPU モードで起きやすい。【一次】[S12]
> 「メモリの不足により音声の合成に失敗し発生する現象です。GPU モードでよく発生します。」[S12]
- 公式 Q&A: 「、」で区切った短い文節が読まれないことがある。【一次】[S12]
> 「現状の音声合成エンジンの仕様になります。前後の無音の長さを長くすると改善することがあるのでお試しください。」[S12]
- ストリーミング合成の説明で、README は次のように注意している（`start_offset` で途中から合成した音声をつなぐ場合の話）。【一次】[S1]
> 「注意点として、別のリクエストで合成した２つの音声を結合すると、つなぎ目の音が不自然になる場合があります。全体の音声が必要な場合は１回のリクエストで合成してください。」[S1]
- エディターには、貼り付けたテキストを句点や改行で分けるかを選ぶ「テキスト自動分割」の設定がある。【一次】[S11]
- 実測記事（CPU、1台の Mac、2026-08-31 公開）: 冥鳴ひまりで1200字を一括で合成すると、エンジンがエラーもログも出さずに停止した（2回中2回）。600字までは正常で、ずんだもん・四国めたんでは1200字でも正常だった。【二次】[S17]
> 「POST /synthesis がHTTPエラーを返すのではなく、応答のないままエンジンプロセスごと停止(接続切断→以降は接続拒否)」[S17]
> 「一括で落ちた同じ1200字を300字×4に分割したら正常に完走した(合計29.25秒)。」[S17]
- 同じ記事: ずんだもんの1200字では、300字×4に分けたほうが一括より3秒速く、音声は文の境目の無音のぶん 1.04 秒長くなった。記事は、クライアント側でタイムアウトと WAV が返ったかの確認を持つべきだとしている。【二次】[S17]

### 10. 処理時間と GPU 版
- 公式 Q&A では、GPU 版は Windows では DirectML 対応 GPU、Linux では Nvidia 製 GPU に対応する。【一次】[S12]
> 「DirectML 対応の GPU を搭載した Windows PC と、Nvidia 製 GPU 搭載の Linux PC に対応しています。」[S12]
- インストーラー版は、初回起動時に CPU 版か GPU 版かを選んでエンジンをダウンロードする。あとから「エンジンの管理」で切り替えられる。Mac 版は GPU モードに対応していない。【一次】[S11]
- 対応する GPU がない PC で GPU モードを選ぶと、エンジンの起動に失敗する。【一次】[S12]
- CPU 実測（2026-08-31、1台の Mac、話者3種、各2回）: RTF（合成時間÷音声の長さ）は 0.11〜0.16 で、3分43秒のナレーションが34秒でできた。`audio_query` は初回 0.68 秒、2回目以降は 0.1 秒未満で、時間のほとんどは波形生成にかかった。【二次】[S17]
> 「RTFは字数を12倍にしても話者を替えてもほぼ0.11のまま動かない。」[S17]
- GPU 別の処理時間を有志が集めた表（10・50・100文字の処理にかかった秒数とその平均）から、近い機種を抜き出す。測った人・エンジンのバージョンがそれぞれ違い、RTX 4070 Ti SUPER の行はない。【二次】[S16]

### 11. セリフの長さ（タイミング）を合成前に出す
- `audio_query` の結果には、各モーラの子音・母音の長さ（秒）が入っている。開始時刻は入っていない。【一次】[S20]【二次】[S15]
- 2026年7月の記事は、前の無音から始めて、モーラ長と句末の無音（`pause_mora`）を順に足し、話速で割って各アクセント句の開始秒を出した。87字の原稿で合計 13.416 秒と計算し、書き出した WAV の実測は 13.44 秒だった（VOICEVOX 0.25.2、ずんだもん）。【二次】[S15]
- 同じ記事は、各音素の長さを256サンプル単位に丸めて足すと実測と一致したと書いている。ただし実装は読んでいないとしている。【二次】[S15]
> 「ただし、これはそう仮定して足し直したら合った、という逆算です。」[S15]
- エンジンのソースでは、秒をフレーム数に直すときに `FRAMERATE = 93.75`（コメントに 24000 / 256）を掛けて丸め、これを音素ごとに行う。記事の逆算はこの実装と合っている。【一次】[S4]
- 疑問形のアクセント句（`is_interrogative` が true で末尾が有声）には、合成時に長さ 0.15 秒のモーラが足される。`/synthesis` の `enable_interrogative_upspeak` が既定で true なので、疑問文は足し算より長くなる。【一次】[S3][S4]
> 「必要に応じて各アクセント句の末尾へ疑問形モーラ（同一母音・継続長 0.15秒・音高↑）を付与する」[S4]
- エディター 0.26.0 で、音声の長さを表示する機能が入った。【一次】[S13]

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。
- **台本は「表示」と「読み」を別に持つ。** セリフごとに `role`・`text`（テロップ用）・`yomi`（任意。あればこちらをエンジンへ送る）を持たせる。m/s²、TNT、数式などは `yomi` で開く。（根拠: [S11][S15][S19]）
- **合成の前に「読みの確認」を人の関門に入れる。** 全セリフに `audio_query` を投げ、返ってきた `kana` を一覧にする。数字（小数・3桁以上）、全部大文字の英字、英単語、単位を含む行を目立たせて人が見る。物理チャンネルでは数値の誤読は内容の誤りになる。（根拠: [S1][S2][S7][S14]）
- **辞書はリポジトリのファイルを正本にし、エンジンへの反映は一方向にする。** 登録の前に発音がカタカナかを検査する。品詞と優先度を明示して、既定値（固有名詞・5）任せにしない。辞書は同じ PC の全企画で共有されるので、他チャンネルと共用する PC では、生成の前にこのチャンネル用のファイルの単語を上書きで入れ直す（`POST /import_user_dict` の `override`。重複した語を上書きするだけなので、他の企画の語は残る点に注意）。起動引数の一覧に辞書の置き場所を変える項目は見当たらない。（根拠: [S1][S8][S9][S10][S14]）
- **MC 用語の辞書候補を最初に作る。** TNT・FPS のような全部大文字の語は1文字ずつ読まれる。mod・Carpet・Flashback・Iris のような語は、未知語なら kanalizer のカタカナ読みになる。どちらも `kana` で確かめてから登録する。（根拠: [S6][S7]）
- **スタイル id は名前から引く。** 設定には `ずんだもん/ノーマル` のように名前で書き、起動時に `/speakers` で id に変える。（根拠: [S1][S18]）
- **1セリフずつ合成し、長いセリフは句点で分ける。** 目安は300字以下（実測は1機種・1環境のみ）。タイムアウトと WAV のサイズ確認を入れ、エンジンが黙って止まったら再起動して続きから作り直す。（根拠: [S12][S17]）
- **タイミングは WAV の実測を正とする。** `audio_query` からの計算は、合成前のテロップ配置の見積もりに使う。計算する場合は、93.75 フレーム/秒の丸めと疑問文の 0.15 秒を入れる。（根拠: [S4][S15]）
- **間（ま）は台本側で制御する。** セリフ内は `pauseLengthScale`、話者が替わるときの間はタイムラインで足す。値は [掛け合い形式.md](../script/掛け合い形式.md) の話速・無音の項目に合わせる。（根拠: [S2][S19]）
- **出力は 24kHz のまま保存し、変換は Remotion 側か最後の書き出しで1回だけ行う。** 上げても品質は上がらないため。ラウドネスは [音量とラウドネス.md](./音量とラウドネス.md) で揃える。（根拠: [S1][S5][S11]）
- **自宅の RTX 4070 Ti SUPER（Windows）では GPU 版（DirectML）をまず試す。** CPU 版でも RTF 0.11 程度の報告があるので、GPU 版で不具合が出たら CPU 版に戻してよい。どちらを使ったかはログに残す。（根拠: [S12][S16][S17]）
- **lab ファイルは口パク（立ち絵の口の開閉）に使える可能性がある。** エディター経由なら書き出せる。API での作り方は要確認。（根拠: [S11]）

## わかっていないこと・要確認
- 単位・記号・数式（m/s、m/s²、km/h、％、℃、×、＝、√、分数、上付きの²）を OpenJTalk／VOICEVOX がどう読むか。公式資料も読めた記事も扱っていない。物理でよく使う表記を並べたテスト文を `audio_query` に通し、`kana` を記録する必要がある（全角・半角の違いも）。
- 小数の読みが崩れる件（63.3 など）が、0.26.x でも起きるか。記事 [S14] には VOICEVOX のバージョンが書かれていない。
- 記事 [S14] の言う優先度「既定の8」が何の既定値か。エンジンの API で省いたときは 5【一次】[S10]、エディターの既定値は未確認。
- エディターのルビ記法 `{対象|よみ}` やメモ記法 `[]` を、エンジンの API がそのまま解釈するか（エディター側の処理かどうか）。未確認。
- `/synthesis` が返す WAV のビット深度。soundfile にサブタイプを指定していないことまでは確認した [S3] が、soundfile の既定値は読んでいない。
- lab ファイルの書式と、API だけで同じ情報（音素とタイミング）を出す方法。
- RTX 4070 Ti SUPER と最新エンジン（0.26.x）、DirectML の組み合わせでの処理時間。表 [S16] には該当する行がない。
- 冥鳴ひまり×1200字で止まった件 [S17] の原因と、GPU 版でも起きるか。
- 調査した README は master ブランチのもので、どのリリースのエンジンと同じかは確かめていない。エディター 0.26.3 の公開日は、変更履歴のページに書かれていない。
- 話者 id の一覧 [S18] を取ったバージョンと日付。
