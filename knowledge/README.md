# knowledge — 動画制作の知見（チャンネルを問わない）

YouTube の仕組み・ポリシー、企画、台本、音声、編集、投稿、分析、法務について、**出典つきで**調べた知見を、話題ごとに1ファイルにまとめたもの。
Minecraft 固有の知見（Mojang の規約、MC の撮影、mod、MC の物理、マイクラ動画の市場）は
[minecraft_physics の knowledge/](https://github.com/mitsuo822/minecraft_physics/blob/main/knowledge/README.md) にある。

- 調査日: 2026-11-19〜20。YouTube のヘルプや規約はよく変わるので、使う前に各ファイルの「参照先」の原文を確かめる。
- 1つの事実は1つのファイルにだけ詳しく書き、他のファイルからはリンクする。

## 書き方の決まり

### 確度

| 表記 | 意味 |
|---|---|
| 【一次】 | 当事者の公式資料を自分で読んで確認した（YouTube ヘルプ・公式ブログ・公式チャンネルの発言、規約の原文、ソフトの公式ページ・ソース、法令・官公庁の資料、プラットフォームの技術者の論文、動画ページの表示値） |
| 【二次】 | Wiki、解説記事、ブログ、本人談・インタビュー、第三者の調査、プラットフォーム以外の研究者の論文 |
| 【未確認】 | 検索結果の要約しか読めていない、出典同士が矛盾する、古くて今も有効か不明 |
| 【実測】 | 自分たちが実際に計測した（MC内の計測は minecraft_physics 側） |

### 推測をしない

- 出典のない事実は書かない。見つからなければ「わかっていないこと・要確認」に書く。
- **「」は原文そのままの引用だけ**に使う。言い換えは地の文で書き、英語の和訳には「（訳）」を付けて原文も併記する。動画・記事・機能の名前は『』で書く。
- 数値には時点（公開日・更新日・取得日）を書く。公式の説明・第三者の分析・個人の経験談を区別し、相関から因果を言わない。
- 提案（どうするか）は事実とは別の「このチャンネルでの使い方（提案）」の節に書き、根拠を `[S番号]` で示す。

### ファイルの形

```markdown
# <題名>

> 対象: <このファイルが扱う範囲>
> 使う場面: <制作のどの工程で読むか>
> 調査日: YYYY-MM-DD
> 関連: [<ファイル名>](<相対パス>), ...

## 要点
- <結論の一文> 【一次】[S1]

## 詳細
### <小見出し>
<事実の文> 【一次】[S1]

## このチャンネルでの使い方（提案）
> ※この節は上の事実から導いた提案で、事実ではない。

## わかっていないこと・要確認

## 参照先
- [S1] <題名> — <発行者> — <URL> — <公開日/更新日> — 取得: YYYY-MM-DD — 原文: 読んだ / 検索要約のみ
```

### 検証の手順

今回の調査は、すべてのファイルを次の3段階で確かめた。追記するときも同じ手順をとる。

1. **調査役が書く**: 一次資料を優先して本文を読み、上の書式で書く。
2. **機械照合**: [`tools/knowledge/check_sources.py`](../tools/knowledge/README.md) で、すべての「」の引用が出典の本文に一字一句あるか、URL が生きているかを照合する。[`lint_knowledge.py`](../tools/knowledge/README.md) で書式を検査する。
3. **反証役が確かめる**: 別の担当が、照合で不一致になった引用、要点の全項目、すべての数値・日付・規約の記述を出典の本文と突き合わせ、合わないものを訂正・削除・格下げする。
