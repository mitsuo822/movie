# 掛け合い形式（ゆっくり解説・ずんだもん解説の2人の会話）

> 対象: 合成音声のキャラクター2人が会話しながら解説する日本の動画形式（ゆっくり実況・ゆっくり解説・VOICEVOX のキャラクターを使う解説）の歴史、役割分担、台本の慣習、テンポと間の作り方。学習効果の研究（対話を見ると学びやすいか）は扱わない。
> 使う場面: キャラクターと役の割り当てを決めるとき、台本を書くとき、音声の生成設定（話速・間）を決めるとき
> 調査日: 2026-11-19 ／ mc_version: 該当なし（Minecraft に依存しない知見）
> 関連: [科学解説の伝え方.md](科学解説の伝え方.md)（対話を観察する学習の研究、音声原則）, [冒頭フック.md](冒頭フック.md), [維持率を上げる構成.md](維持率を上げる構成.md), [../channel/AI音声チャンネルの事例とリスク.md](../channel/AI音声チャンネルの事例とリスク.md)（収益化・商標騒動）, [../audio/VOICEVOX利用規約.md](../audio/VOICEVOX利用規約.md), [../audio/キャラクター立ち絵の規約.md](../audio/キャラクター立ち絵の規約.md), [../editing/テロップ・字幕.md](../editing/テロップ・字幕.md), [../editing/カット割りとテンポ.md](../editing/カット割りとテンポ.md), minecraft_physics リポジトリの `knowledge/market/日本のマイクラ動画ジャンル.md`（ニコニコ時代のマイクラのゆっくり実況）

## 要点

- 「ゆっくり」は、東方Projectの博麗霊夢と霧雨魔理沙の頭部をモチーフにした2ちゃんねるのアスキーアート「ゆっくりしていってね！！！」が由来。2008年2月ごろ、M.U.G.E.N 向けの「ゆっくり」のキャラクターに SofTalk（AquesTalk を使う読み上げソフト）の声が使われたのを機に、その声が「ゆっくりの声」として定着した。【二次】[S1][S2]
- ゆっくり実況は2008年後半ごろに現れ、2009年後半から投稿数が増えた（ASCII.jp の2013年の集計）。ゲーム実況に使うものが「ゆっくり実況」、アニメ・漫画・歴史などの説明に使うものが「ゆっくり解説」と呼ばれる。【二次】[S1]
- 2011年公開の「ゆっくりMovieMaker」が、セリフを入力すると音声・字幕・口パクがタイムラインに自動で並ぶ仕組みを作り、制作の手間を大きく減らした。この普及がジャンルの拡大を後押ししたと報じられている。【二次】[S1][S3]
- 2021年8月1日に無料の音声合成ソフト VOICEVOX が公開され、最初から使えたずんだもんの声を使ったユーザー生成コンテンツが動画投稿サイトなどで数多く作られ、人気と認知度が上がった。商用・非商用を問わず無料で使えることが普及の一因として挙げられている。【二次】[S4][S5]
- ゆっくり解説の定番の役割は「霊夢＝視聴者の代わりに疑問を出す役」「魔理沙＝答えをわかりやすく説明する役」とされる。ただし出典は実践者1人の解説記事で、体系的な調査ではない。【二次】[S16]
- VOICEVOX の公式サイトは、キャラクターの性格・年齢などのプロフィール（「ボイボ寮」）と、**キャラクター同士の呼び方の一覧表**を公開している。一覧表は「必ずしも遵守する必要はなく、自由に改変して頂いても問題ありません」とされる。【一次】[S11]
- ずんだもんの公式設定は「やや不幸属性が備わっており、ないがしろにされることもしばしば」、四国めたんは「基本的にタメ口」「若干ツンデレ気味」。キャラクターの性格は役の割り当ての材料になる。【一次】[S9][S10]
- 台本の実践として、一方が長く話し続ける・片方が相槌だけになるのを避け、「質問→答え→リアクション→補足→驚き→結論」の流れで回す、軽いボケとツッコミは30〜60秒に1回くらいで十分、1文は20〜30文字程度、台本は1行1文で書く、が勧められている（同じ著者の記事群）。【二次】[S16][S17][S18][S19]
- 合成音声に台本を読ませる方式には、フィラーや言い直しがなく字幕を同時に出せる、一部だけ作り直せる、という利点がある。教員（小椋賢治）の体験では、同じ講義が肉声の録画の半分の長さになった。【二次】[S20]
- VOICEVOX ENGINE の音声合成クエリには「全体の話速」「音声の前の無音時間」「音声の後の無音時間」「句読点などの無音時間（倍率）」があり、掛け合いのテンポと間をプログラムで一括指定できる。【一次】[S21][S22]
- YouTube の収益化ポリシーは「複数のエピソードにわたって特定のキャラクターを追うシリーズ」を許可される例に挙げる一方、「キャラクターが何度も同じ状況に置かれ、同じ結末を迎える動画」を許可されない例に挙げる。決まったキャラクターで続けること自体は問題ないが、毎回同じ型の繰り返しは避ける必要がある。【一次】[S23]

### 台本の慣習（実践者の解説）

以下は同じ著者（ゆっくり動画の自動化ツールを販売）の note 記事群の主張で、効果を検証したデータは示されていない。【二次】

- **避けること**: 一方が長く話し過ぎる（一人語りが長くなり単調になる）、相槌だけのキャラクターがいる（会話に変化がなくなる）。【二次】[S17]
- **流れ**: 話題ごとに「質問→答え→リアクション→補足→驚き→結論」を意識する（「キャッチボール形式」）。【二次】[S17]
  > 「キャッチボール形式とは、キャラクター間でテンポ良く会話を交わす手法です。」[S17]
- **ボケの量**: 「ボケは「大爆笑」ではなく「小さなズレ」で十分」。【二次】[S16]
  > 「目安としては、30〜60秒に1回くらい軽いツッコミが入る程度で問題ありません。」「解説動画で一番大事なのは、笑わせることではなく、最後まで見てもらうことです。」[S16]
- **キャラのぶれ**: 機械的な敬語、魔理沙が「〜です」調で霊夢が「〜だぜ」と話す、全部のセリフが同じ長さ・同じトーン、を NG とし、「キャラごとに語尾・テンションを固定する」。【二次】[S16]
- **構成**: 導入（疑問の提示）→本編（解説→反応→解説…）→まとめ（要点の整理、次回予告や問いかけ）。【二次】[S16]
- **文の長さ**: 「長すぎる文章は聞き取りにくいので、1文を20〜30文字程度にするのが理想。」【二次】[S18]
- **台本の書式**: 「台本の1行につき、必ず1文だけを書く」「改行は「意味のまとまり」で行う」「句読点を詰め込みすぎない」。表計算ソフトで A列＝話者、B列＝セリフにして CSV にし、ゆっくりMovieMaker4 に読み込ませる。【二次】[S19]
- **画面**: ゆっくり実況は場面の切り替えが少なく背景が一定で単調になりやすく、立ち絵や字幕をランダムに動かす効果がよく使われる。【二次】[S3]

合成音声に台本を読ませる方式の利点（教員が反転授業の講義動画をゆっくり解説で作った体験、2022年7月）:【二次】[S20]

> 「ゆっくり解説では，あらかじめ台本を作成しておいて，その台本を音声合成ソフトに発音させるため，フィラーや言い直しはありません．」[S20]
> 「音声と同時に字幕が画面に表示されるため，受講生の聴覚あるいは環境に制約があっても講義の内容を届けることができます．」[S20]

- 内容を更新するとき、肉声の講義は撮り直しが要るが、ゆっくり解説は該当部分だけ作り直せばよい。【二次】[S20]
- 同じ内容の講義を比べたところ、「ゆっくり解説のほうが時間が半分に短縮されました．」（1人の体験。条件は記事に詳しく書かれていない）。【二次】[S20]

### テンポと間（音声側の調整）

- ゆっくりMovieMaker4 は、テキストを入力すると音声クリップが生成され、字幕とリップシンク（口パク）が同時にタイムラインに置かれる。VOICEVOX・CeVIO AI・A.I.VOICE・VOICEPEAK なども使える。【二次】[S3]
- VOICEVOX ENGINE は、`/audio_query` で得た音声合成用のクエリを編集してから `/synthesis` に渡すことで音声を調整できる（README の例は話速を1.5倍にするもの）。【一次】[S21]
- 音声合成用のクエリ（`AudioQuery`）のうちテンポと間に関わる項目（master ブランチ、取得 2026-11-19）:【一次】[S22]

| 項目 | ソースコード上の説明 | 確度・出典 |
|---|---|---|
| `speedScale` | 「全体の話速」 | 【一次】[S22] |
| `pitchScale` / `intonationScale` | 「全体の音高」／「全体の抑揚」 | 【一次】[S22] |
| `prePhonemeLength` | 「音声の前の無音時間」 | 【一次】[S22] |
| `postPhonemeLength` | 「音声の後の無音時間」 | 【一次】[S22] |
| `pauseLength` | 「句読点などの無音時間。nullのときは無視される。デフォルト値はnull」 | 【一次】[S22] |
| `pauseLengthScale` | 「句読点などの無音時間（倍率）。デフォルト値は1」 | 【一次】[S22] |

- 読み方は「AquesTalk 風記法」で直せる。アクセント句は `/` か `、` で区切り、「`、` で区切った場合に限り無音区間が挿入される」。句末に全角の `？` を付けると疑問文の発音になる。【一次】[S21]
- README は、別々のリクエストで合成した2つの音声をつなぐと、つなぎ目の音が不自然になる場合があると注意している（ストリーミング合成の説明の中）。【一次】[S21]

## このチャンネルでの使い方（提案）

> ※この節は上の事実から導いた提案で、事実ではない。

- **聞き手役に「予想」と「疑問」を言わせる。** 定番の「視聴者の代わりに疑問を出す役」を、チャンネルの構成の「予想」区間（現実の物理ではどうなるか）に当てる。聞き手が間違った予想を言い、解説役が実測で答える形にすると、役割が台本の構造と一致する。（根拠: [S16][S17]。予想させることの学習効果は [科学解説の伝え方.md](科学解説の伝え方.md) で確認する）
- **キャラクターは公式設定と矛盾しない役にする。** 例えば、ずんだもん（「ないがしろにされることもしばしば」）を驚いたり間違えたりする聞き手に、四国めたん（「はっきりした芯のある声」）や青山龍星（「冷静なストッパー枠」「重厚で低音な声」）を解説役にする、などが候補。決めるのは人の関門で。（根拠: [S5][S9][S10][S13]）
- **呼称表を台本生成のルールに入れる。** 一人称・二人称・相手の呼び方を辞書として持ち、台本の自動チェックでぶれを検出する。（根拠: [S11][S16]）
- **台本は「話者・セリフ」の表で、1行1文にする。** そのまま VOICEVOX ENGINE と Remotion に流せる形にし、30字を超える行を警告する。（根拠: [S18][S19][S21]）
- **間は数値で一括管理する。** `speedScale`・`pauseLengthScale`・`postPhonemeLength` をキャラクターごとの既定値として持ち、ボケの後などだけ個別に伸ばす。1つのセリフは1回のリクエストで合成し、途中で分けない。（根拠: [S21][S22]）
- **ボケの頻度は目安として使い、数値は実測で決める。** 「30〜60秒に1回」は実践者の目安でしかないので、公開後の維持率で調整する（指標の見方は維持率のファイル）。（根拠: [S16]、[維持率を上げる構成.md](維持率を上げる構成.md)）
- **毎回同じ型・同じオチにしない。** 同じキャラクターのシリーズは許可例だが、キャラクターが何度も同じ状況に置かれて同じ結末を迎える動画は不可例。実験の題材・装置・結果が毎回違うことが、この形式を続ける前提になる。（根拠: [S23]、詳しくは [../channel/AI音声チャンネルの事例とリスク.md](../channel/AI音声チャンネルの事例とリスク.md)）

- 2人の掛け合いが1人のナレーションより視聴維持率が高いかの、YouTube 側や第三者の定量データ（見つからなかった）。学習効果の研究は [科学解説の伝え方.md](科学解説の伝え方.md)。
- 解説動画に向く話速（`speedScale`）や句読点の間の具体的な値の出典（見つからなかった）。
- ASCII.jp（2013・2015年の集計）、ITmedia NEWS、ねとらぼ、ニコニコニュースORIGINAL（2021年8月4日の投稿者インタビュー）の原文は未読で、Wikipedia の記述を経由している。
- 実践者の台本のコツ（[S16]〜[S19]）は1人の著者のもので、著者は自動化ツールを販売している。別の制作者の資料で裏付けたい。
