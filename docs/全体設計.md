# 全体設計

状態: 叩き台（2026-11-18）。未実装。
前提: 自宅のWindows PC（RTX 4070 Ti SUPER 16GB）で動かす。以前の設計案（commit `40f36c8`）の「制作台帳を中心に、工程をプログラムでつなぐ」方針を引き継ぐ。

## 1. 担当範囲

```
チャンネル側のリポジトリ                       movie（このリポジトリ）
（例: minecraft_physics）
テーマ・実験・計測・撮影・台本  ──ledger.json──→  ① 台帳の検証
                                                 ② ナレーション音声（掛け合い対応）
                                                 ③ 字幕・タイミング計算
                                                 ④ 組立（Remotion）: 長尺 16:9
                                                 ⑤ ショート: ドパガキ編集 9:16
                                                 ⑥ 自動検査
                                                 ⑦ アップロード（非公開）→ 人が公開
                                                 ⑧ 視聴データの取り込み → knowledge/youtube/
```

## 2. 部品

| 工程 | 第一候補 | 理由・注意 |
|---|---|---|
| 台帳の検証 | JSON Schema（Python） | 形式の誤りを最初に止める |
| ナレーション | VOICEVOX（ローカルのエンジンAPI） | 音素（モーラ）単位の時刻が返るので、字幕と画面の切り替えを語りに正確に合わせられる（以前の設計案で、ソースを読んで確認済み）。キャラクターごとの利用規約とクレジット表記に従う |
| 読みの修正 | VOICEVOXのユーザー辞書 | 物理用語・MC用語の誤読を辞書で直す。辞書はgitで管理する（`knowledge/voice/`） |
| 字幕・タイミング | Python | モーラの時刻から字幕の区切りと表示時間を計算する |
| 組立 | Remotion | 映像素材・グラフ・字幕・数式・効果音を、台帳からプログラムで並べる。長尺とショートでテンプレートを分ける |
| グラフ・数式 | Remotion の部品（SVG）、KaTeX | 計測データ（CSV）から、理論の線と実測の点を描き、動きを付ける |
| 書き出し | Remotion → ffmpeg | 音量の正規化（YouTube向けにラウドネスをそろえる）もここで行う |
| 検査 | ffmpeg ＋ Python | 黒画面・無音・音割れ・音量・字幕のはみ出し・尺・台帳との照合 |
| 投稿 | YouTube Data API v3 | 監査前は非公開に固定される（`YouTube運用.md`） |

## 3. 長尺とショートの関係

- ショートは長尺の台帳から作る。台帳の「見せ場」の印（`highlight`）を元に、LLMがショートの台本（フック → 3〜5拍 → オチ）を作る。
- 縦画面の映像は、チャンネル側が9:16で撮った素材を優先する。なければ16:9から切り抜く（画質が落ちるので、あくまで代わりの手段）。
- 演出の仕様は `ショート編集.md`。
